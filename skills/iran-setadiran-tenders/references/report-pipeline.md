# خط تولید گزارش PDF (مهارت fa-pdf + صفحه‌بندی اندازه‌گیری‌شده)

گزارش نهایی با محیط آماده مهارت `fa-pdf` ساخته می‌شود (`~/.zcode/workspace/default/pdf-build/`): Node + playwright-core + Chrome سیستم، فونت وزیرمتن، قالب پایه `checklist.html`.

## چرخه کامل

1. **داده**: `scripts/fetch_announcements.js` و `scripts/fetch_details.js` را از پوشه کاری پروژه اجرا کن → `<cwd>/setadiran-data/final_data.json`.
2. **مولد گزارش**: از `assets/report/report-template.js` به‌عنوان اسکلت استفاده کن (کپی به `pdf-build/`) و سازنده‌های کارت را برای شهر هدف از الگوی اجراشده تکمیل کن. نسخه کامل و اجراشده برای فردیس در `pdf-build/gen_report.js` همان جلسه موجود است — بهترین مرجع کپی.
3. **اندازه‌گیری**: `assets/report/measure.js` ارتفاع واقعی هر کامپوننت (`data-m`) را با Chrome اندازه می‌گیرد → `heights.json`.
4. **صفحه‌بندی**: موتور قالب، اجزا را با بودجه‌ی پیکسلی در صفحات A4 جای می‌دهد (bin-packing).
5. **رندر**: `node render.js report.html report.pdf` → PDF وکتور + PNG هر صفحه + `OVERFLOW-DIAG`.
6. **کنترل**: PNGها را به agent `judge` بده؛ در صورت fail، اصلاح و فقط صفحات تعمیرشده را دوباره judge کن.

## قواعد سخت‌گیرانه (هرکدام یک بار هزینه واقعی داشته)

- **`.page` با ارتفاع ثابت (297mm) محتوای سرریز را بی‌صدا می‌بُرد** — OVERFLOW-DIAG هم همیشه نمی‌گیرد چون flex آیتم‌ها را فشرده می‌کند. هرگز به حدس اکتفا نکن؛ همیشه ارتفاع واقعی کامپوننت‌ها را اندازه بگیر و صفحه‌بندی را محاسبه کن. کارت مناقصه‌ی کامل ≈ ۳۳۰-۳۵۰px، کارت خدمات ≈ ۲۱۰-۳۱۰px است.
- **measure.html باید دقیقاً همان CSS و همان ساختار جدول (با thead و قواعدی مثل `td.num { white-space:nowrap }`) را داشته باشد** — وگرنه عرض ستون‌ها در اندازه‌گیری با رندر واقعی فرق می‌کند و صفحات جدول‌دار سرریز می‌شوند (دو بار هزینه واقعی داشت).
- **divهای mhead در measure.html حتماً بسته شوند** — div بازمانده، ارتفاع همه اجزای بعدی را می‌بلعد و صفحات خالی می‌سازد.
- **صفحات ادامه‌ی جدول باید `<thead>` کامل را تکرار کنند** وگرنه ردیف‌ها بدون کادر رندر می‌شوند. بودجه‌ی این صفحات را ~۷۰px کمتر بگیر (`BUDGET_TABLE`) چون سربرگ ممکن است دوخطی شود.
- بودجه‌های تثبیت‌شده برای A4 با پدینگ `10mm 12mm 8mm`: محتوا ≤ ۹۱۵px (جدول‌دار ۸۶۸px). اگر سربرگ/پانوشت را تغییر دادی، دوباره کالیبره کن.
- فونت‌ها با مسیر نسبی `fonts/...` و `document.fonts.ready` قبل از `page.pdf()`؛ `preferCSSPageSize: true` + `margin: 0`.
- `overflow:hidden` روی html/body/.page ممنوع — سرریز را مخفی می‌کند، نه حل.
- PDF نهایی فقط با `page.pdf()` (وکتور)؛ PNG فقط برای judge.

## ساختار گزارش تثبیت‌شده (پذیرفته‌شده توسط judge)

- **صفحه ۱ (جلد)**: kicker + h1 با accent رنگی + lead + ۵ جعبه آمار (کل/مناقصه/خدمات/کالا/مزایده) + دستگاه‌های اصلی + جدول خلاصه مناقصات + یادداشت خدمات. اگر جا نشد، جدول‌های خلاصه را به یادداشت متنی تبدیل کن نه اینکه فونت را خرد کنی.
- **بخش ۱ — مناقصات**: کارت هر مناقصه با ۱۴ فیلد kv دوستونه (دستگاه، نوع فرآیند، استان/شهر عملیات، حوزه فعالیت، برآورد مالی، تضمین، هزینه اسناد + حساب واریز، مهلت دریافت اسناد، مهلت ارسال پاکت، بازگشایی، اعتبار پیشنهاد، مسئول ثبت، کد پستی) + شرح + آدرس + لینک رسمی.
- **بخش ۲ — خدمات/پیمانکاری**: شرح کامل + جدول اقلام خدمت + توضیحات خریدار (کادر آمبر) + لینک.
- **بخش ۳ — کالا**: جدول فشرده.
- **بخش ۴ — مزایده**: جدول با قیمت پایه (ریال + معادل تومان) با سربرگ تکرارشونده.
- **کادر روش‌شناسی** در صفحه آخر: منبع، فیلتر، تاریخ تهیه (شمسی + میلادی)، نکته لاگین برای اسناد کامل.
- پانوشت همه صفحات: «صفحه X از N» + تاریخ تهیه.

## فرمت اعداد و متن

- قیمت‌ها: رقم‌ها فارسی با جداکننده هزار + «ریال» + معادل تقریبی میلیارد/میلیون تومان.
- همه اعداد نمایشی فارسی (تیتر، مهلت‌ها، ردیف‌ها)؛ فقط URLها لاتین و LTR.
- ارقام داخل عناوین اگهی هم فارسی شوند (toFa روی عنوان‌ها، نه روی URL).
