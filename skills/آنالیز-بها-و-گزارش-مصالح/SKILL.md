```

```

ریپوی گیت‌هاب: `najafibehzad/analiz-masaleh-webapp` (private، برنچ `main`).

> نام قبلی این اسکیل: `iran-analiz-webapp` — برای سازگاری در جست‌وجو و ارجاع‌های قدیمی نگه داشته شده.

## ۰) تصمیم مسیر — کدام روش؟

| وضعیت | مسیر |
|---|---|
| فایل **اکسل** یا PDF متن‌دار برآورد داری | ✅ همین وب‌اپ — `GET /api/template` |
| فقط **PDF اسکن‌شده/تصویری** داری | وب‌اپ با OCR (نیاز به گیت‌وی ۹روتر) **یا** مسیر دستی `iran-analiz-fehrest-maghadir` |

| فقط نرخ/شرح یک ردیف فهرست‌بها را می‌خواهی | `GET /api/fehrest` + کاتالوگ `data/fehrest/*.json` |

**قاعدهٔ کلی:** ورودی PDF/عکس خطاپذیر است؛ تا وقتی اکسل ممکن است، اکسل بده. در سندباکس هم تولید از مسیر API مطمئن‌تر از مرورگر است.

## ۲) API — قرارداد کامل

| متد | مسیر | ورودی | خروجی |
|---|---|---|---|
| GET | `/api/health` | — | `{ok, port}` |
| GET | `/api/template` | — | دانلود «قالب کلی برآورد» اکسل (xlsx، ۴ شیت با کاتالوگ فهرست‌بها) — ~۲۵۰KB |
| GET | `/api/fehrest` | — | `{ok, catalogues:[{slug,reshteh,sal,label,count,source}]}` |
| GET | `/api/avamel` | — | `{ok, groups, mabaniCodes, balasariItems}` — کتابخانهٔ عوامل برای فرم نرخ‌ها |
| POST | `/api/parse` | بدنهٔ **خام فایل** (`application/octet-stream`) | xlsx: `{ok, meta, fasls, rows, rowsCount, sheetName, warnings}` · PDF/عکس: `{ok, jobId, kind:'pdf'}` |
| POST | `/api/generate` | JSON `{rows, meta, coeffs, params}` | `{ok, jobId}` |
| GET | `/api/job?id=` | — | `{ok, state:'running'\|'done'\|'error', progress, result, error, elapsed}` |
| POST | `/api/open` | `{path}` — **فقط داخل `C:\Desktop`** | `{ok}` |

پارس xlsx **همگام** است؛ پارس PDF/عکس **پس‌زمینه‌ای** (job) و چند دقیقه طول می‌کشد.

```json

  "meta": {"proje":"","karfarma":"","peymankar":"","tarikh":"۱۴۰۵/۶/۲۹",
           "reshteh":"راه، راه‌آهن و باند فرودگاه","sal":"۱۴۰۴"},
  "coeffs": {"balasari":1.41,"mantaghe":1.0,"tajhiz":0,"baravordRasmi":0,
             "zaribJoz":null,"targetKol":1.1555,
             "balasariItems":[["شرح بخش بالاسری",17.5]],
             "deriveBalasari":false},
  "params": {"gammaAsph":2.25,"bitumPct":0.052,"gammaAgg":1.6,
             "mixTonRate":13500000,"binTonRate":13000000,"cemTonRate":13176366,"mortarCemT":2.5,
             "avamel":{"14010102":641708.2}}

```

| فیلد | معنا |
|---|---|
| `coeffs.zaribJoz` | `{فصل: ضریب}` — حالت «جزء فصل‌ها». `null` وقتی `targetKol` می‌دهی |
| `coeffs.targetKol` | ضریب کل هدف؛ **سنگین‌ترین فصل (لنگر)** خودکار حل می‌شود → `summary.solvedAnchor` |
| `coeffs.baravordRasmi` | ۰ → خودش `sumBase × balasari × mantaghe + tajhiz` را می‌گذارد |
| `coeffs.deriveBalasari` | `true` → ضریب بالاسری از `balasariItems` حل می‌شود: `100/(100−P₀)` |
| `params.bitumPct` | **اعشاری** است (۵/۲٪ → `0.052`) |
| `params.avamel` | نرخ‌های دستی عوامل (کد → ریال) که روی کتابخانهٔ عوامل سوار می‌شود |
| `rows[].star` | ردیف ستاره‌دار (غیرپایه) |

⚠️ **`coeffs` ضریب طبقات ابنیه را ندارد** — به بخش ۵ نگاه کن.

## ۳) ورودی — قالب کلی برآورد (روش پیشنهادی)

```
GET /api/template  →  قالب-برآورد-مناقصه.xlsx
```

چهار شیت: **برآورد** (انتخاب سال + رشته + مشخصات + ضرایب + جدول ۴۰۰ سطری + خلاصهٔ خودکار) · **کاتالوگ** (کل ردیف‌های فهرست‌بها) · **راهنما** · **فصل‌ها**.

**چندرشته‌ای** (مناقصه می‌تواند هم راه داشته باشد هم ابنیه):
- **B3** = سال فهرست‌بها (کشویی — یک سال برای کل مناقصه)
- **B4** = رشتهٔ پیش‌فرض سطرها (کشویی) — ستون «رشته» هر سطر پیش‌فرض از این می‌آید و قابل تغییر است
- **ستون A هر سطر** = رشتهٔ همان سطر (کشویی) → هر سطر از کاتالوگ رشتهٔ خودش پر می‌شود

**ستون‌ها:** A رشته | B فصل | C شماره ردیف | D شرح ردیف | E واحد | F نرخ فهرست‌بها | G بهای واحد (قابل ویرایش) | H مقدار | I بهای کل | J ستاره‌دار. ستون L پنهان = «کد مؤثر».

**سه راه ورود آسان‌تر (پیاده‌شده):**
1. **کشویی هر سطر** — سلول «شماره ردیف» فقط کدهای رشتهٔ همان سطر را نشان می‌دهد: `OFFSET(... MATCH($A15&"|"&سال&"|*" ...) ...)`.
2. **چسباندن «کد + شرح»** — ستون کمکی پنهان، شش رقم اول را به‌عنوان کد جدا می‌کند: `IF(ISNUMBER(VALUE(LEFT(TRIM($C15),6))),LEFT(TRIM($C15),6),"")`. همهٔ جست‌وجوها روی این ستون کار می‌کنند.
3. **جست‌وجوی کلیدواژه** — B12 کلیدواژه، ستون «مطابقت» شیت کاتالوگ با `SEARCH` روی شرح؛ کاربر فیلتر ۱ می‌زند.

سال در فرمول‌ها با `SUBSTITUTE` به ارقام فارسی نرمال می‌شود (کاربر ممکن است «1404» لاتین بزند).
بهای کل = `IF(AND(G15<>"",H15<>""),G15*H15,"")`. خلاصهٔ برآورد در ستون I.

**مسیر اطمینان دوم:** اگر فایل بدون محاسبهٔ فرمول ذخیره شده باشد، خود وب‌اپ ردیف‌ها را **از کاتالوگ رشتهٔ هر سطر** تکمیل می‌کند (`lib/fehrest.mjs` → `enrichRows`) — فقط فیلدهای **خالی**؛ مقدار دستی کاربر هرگز بازنویسی نمی‌شود.
پارسر ردیفی را که **مقدار + کد** دارد ولی نرخش فرمولی و محاسبه‌نشده است هم می‌خواند (`noPrice`) و نرخش را از کاتالوگ پر می‌کند.

### کاتالوگ فهرست‌بها
`data/fehrest/*.json` — هر فایل یک (رشته، سال). وضعیت فعلی: **راه ۱۴۰۴ (۸۹۲ ردیف)** و **ابنیه ۱۴۰۴ (۱۵۶۵ ردیف)**.
ردیف‌های بدون بهای واحد (ستاره‌دار) و کسر بهاها هم نگه داشته شده‌اند تا شرح/واحدشان خودکار بیاید.
منبع خام روی ماشین کاربر: `C:\Users\behzad\Documents\BahaRah1404\data.js` و `BahaAbnieh1404\data.js`.

افزودن رشته/سال جدید:
```bash
node tools/import-fehrest.mjs "<path/data.js>" "<نام رشته>" <سال> <slug>
```
سپس قالب را از نو دانلود کن.
⚠️ دادهٔ رشته‌های **تاسیسات برقی/مکانیکی** روی این ماشین نیست؛ اگر کاربر خواست، فایل فهرست‌بهایش را بگیر و با همین دستور اضافه کن.

### نکات پارسر اکسل
- شیت با نام «برآورد»/«فهرست مقادیر» اولویت دارد؛ سرستون از ترکیب «شرح + بهای واحد + مقدار» در ۸۰ سطر اول پیدا می‌شود.
- اگر فایل چند شیت دارد، **پرردیف‌ترین شیت** برداشته می‌شود؛ نتیجهٔ غلط → شیت مقصد را جدا کن.
- ردیف‌های خالی و خلاصه/جمع نادیده گرفته می‌شوند و هشدار «سطر نادیده گرفته شد» نمی‌دهند.
- مقادیر متنی (سال، تاریخ، نام) با ارقام فارسی دست‌نخورده می‌مانند؛ فقط اعداد برای محاسبه به لاتین تبدیل می‌شوند.
- کد ردیف با صفر ابتدایی (`010307`) باید **متن** باشد نه عدد.
- نرمال‌سازی ZWNJ در سرستون‌ها انجام می‌شود (مثل «ستاره‌دار») — وگرنه ستون ستاره‌دار پیدا نمی‌شود.
- ضرایب و مبلغ تجهیز از بلوک بالای سرستون خوانده می‌شوند؛ «مبلغ برآورد هزینه اجرای کار» درج‌شده در فایل با محاسبهٔ خودمان مقایسه و اختلافش نمایش داده می‌شود.

## ۵) موتور تجزیه بها — جدول ۵ و ۶

**منبع معتبر:** دستورالعمل شماره **۹۶/۱۲۳۲۵۷۹** مورخ ۱۳۹۶/۰۳/۳۱ سازمان برنامه و بودجه —
«دستورالعمل نحوه ارائه تجزیه بها، آنالیز بها همراه با پیشنهاد قیمت توسط پیمانکاران».
نسخهٔ PDF: `https://www.sharifsoft.com/wp-content/uploads/SharifSoftFiles/Circular/عمومی/tajziyeh_baha_1232579.pdf`

### قواعد پیاده‌شده
- چهار گروه عوامل: **نیروی انسانی | ماشین آلات و ابزار | مصالح | حمل**.
- ستون‌ها: کد عامل | شرح عامل | واحد | **مقیاس** | **مقدار مقیاس** | بهای واحد عامل | **ضریب** | بهای کل.
- **بهای کل = مقدار مقیاس × بهای واحد عامل × ضریب**.
- جمع هر گروه + **درصد به قیمت ردیف**؛ پایان: **جمع واحد کار**، **جمع بهای واحد ردیف با ردیف‌های معادل (× ضریب منطقه‌ای)**، **مقایسهٔ پیشنهاد نسبت به برآورد**.
- نرخ مصالح در **محل تأمین**؛ حمل = بارگیری + حمل + باراندازی (بند ۳-۴).
- جدول ۵ برای **ردیف‌های جدول ۲** (حدود ۸۰٪) و **حداکثر ۵۰ ردیف** (بند ۳-۳).
- **جدول ۶**: `ضریب بالاسری = ۱۰۰ ÷ (۱۰۰ − P₀)`؛ P₀=۲۹/۰۸٪ → **۱/۴۱۰۰** (غیرعمرانی)، P₀=۲۴/۸۱٪ → **۱/۳۳۰۰** (عمرانی). ردیف‌ها = پیوست ۲ فهرست‌بها (بالاسری عمومی ۱-۱…۱-۱۷ + بالاسری کار ۲-۱…۲-۷).
- **آنالیز مآخوذ**: برای ردیف بدون مبانی، نزدیک‌ترین ردیف هم‌خانواده (همان گروه فهرست‌بها با نزدیک‌ترین بهای واحد) برداشت و مبانی با نسبت بهای واحد پایه مقیاس می‌شود.

### «ضریب» ستون جدول ۵ = ضریب تناسب
`ضریب تناسب هر ردیف = بهای واحد فهرست ÷ جمع عوامل پایه` (per-row).
در پروژهٔ قدس بازهٔ **۱/۷۸۲۰ تا ۴/۷۰۸۴**. این ضریب **نه** بالاسری است، **نه** منطقه‌ای، **نه** پیشنهادی. قاطی نکن.

⚠️ **آنالیز باید غیرِ چرخشی باشد:** اگر ضریب را طوری حل کنی که جمع آنالیز همیشه برابر بهای ردیف شود، «مقایسه» همیشه ۰٪ می‌شود و آنالیز بی‌ارزش است. مقایسهٔ واقعی در پروژهٔ قدس از **−۸۴/۶٪ تا +۱۲۷/۳۷٪** در نوسان است.

### کتابخانهٔ مبانی — گسترش
در `data/mabani.json` کلید کد ردیف اضافه کن:
```json
"150803": { "fasl":15, "vahed":"کیلوگرم", "sharh":"…", "source":"tadkar", "zarib":1.2218,
  "items": { "نیروی انسانی":[["14010102",0.02],["14040101",0.005,756558.60]],
             "ماشین آلات و ابزار":[], "مصالح":[], "حمل":[] } }
```
قلم = `[کد عامل، مقدار مقیاس]`، با نرخ اختیاری `[.., .., نرخ]` و ضریب اختیاری `[.., .., نرخ, ضریب]`.
مقدارهای فعلی از **جدول ۵ رسمی تدکار پروژهٔ قدس** (۱۳۰۸۰۹، ۱۳۰۸۰۸، ۱۲۰۱۰۲، ۱۲۰۱۰۴، ۰۱۰۳۰۷، ۰۸۰۱۰۲) و گزارش آنالیز آسفالت همان پروژه (۶ ردیف دیگر) استخراج شده‌اند. رندرهای مرجع: `pdf-extract/out-tadkar/jadval-5/page-*.png`.

## ۶) دانش دامنه‌ای — ضرایب، ستاره‌دار، حمل، مصالح

### ترتیب اعمال ضرایب (بند ۲-۸ دستورالعمل کاربرد فهرست‌بها)
```
Σ(مقدار × بهای واحد پایه)
  → × ضریب طبقات        (فقط ابنیه — پیوست ۲)
  → × ضریب منطقه‌ای
  → × ضریب بالاسری
  → + هزینه تجهیز و برچیدن کارگاه (مقطوع — بدون ضریب)
  = برآورد هزینه اجرای کار
  → + مالیات بر ارزش افزوده ۱۰٪
```

2. **`agent-browser` بین دو فراخوانی Bash وضعیت را از دست می‌دهد** (سندباکس دیمن را می‌کشد) → همهٔ گام‌ها را در **یک** `agent-browser batch` بزن.
3. `wait --text` با آرگومان زمان‌دار در batch اتصال CDP را می‌بندد؛ از `wait --text "..."` ساده استفاده کن یا با پول API منتظر بمان.
4. **سشن مرورگر بیش از ~۲۵ ثانیه زنده نمی‌ماند** → هر انتظار طولانی (تولید PDF) با مرورگر شکست می‌خورد. برای تست UI: کلیک بزن، ۴ ثانیه صبر کن، بعد **از بیرون مرورگر** منتظر پوشهٔ خروجی روی دسکتاپ بمان. برای تولید واقعی از مسیر API استفاده کن.
5. `agent-browser eval` در دنیای ایزوله اجرا می‌شود و `document.getElementById` ممکن است `null` بدهد — برای خواندن وضعیت از `get text`/`get attr` استفاده کن.

### عدد و محاسبه
6. **گرد کردن لنگر:** `zaribJoz` لنگر تا ۴ رقم اعشار گرد می‌شود، پس ضریب کل حاصل مثلاً ۱/۱۵۵۴۷ می‌شود نه دقیقاً ۱/۱۵۵۵ (خطا ~۰/۰۰۳٪). اگر دقت مطلق لازم است، هدف را با ۴ رقم اعشار انتخاب کن.
7. اعداد در PDF با ممیز فارسی `/` چاپ می‌شوند (مثل `1/1555`) — برای مقایسهٔ خودکار اول `/`→`.` و ارقام فارسی→لاتین.
8. **گردکردن فقط یک‌بار** روی حاصل‌ضرب ضرایب (بند ۶).

### مسیر و فایل
9. `/api/open` فقط مسیرهای زیر `C:\Desktop` را می‌پذیرد.
10. `desktop` در کد `C:/Desktop` است (دسکتاپ غیراستاندارد همین ماشین) — **نه** `C:\Users\behzad\Desktop`.
11. اگر پوشهٔ خروجی وجود داشته باشد، **ساعت** به نامش اضافه می‌شود — فایل قدیمی را با جدید قاطی نکن.

### انتشار روی گیت‌هاب (تلهٔ تأییدشده)
`git push` از داخل سشن **کار نمی‌کند** — یک‌بار بی‌صدا و یک‌بار با `could not read Username for 'https://github.com': terminal prompts disabled`. `git fetch` هم نامطمئن است.
→ انتشار از مسیر `gh api --method PUT repos/<owner>/<repo>/contents/<path> --input <body.json>`
(بدنه: `{"message":...,"content":"<base64 -w0>","sha":"<sha فعلی فایل، فقط برای ویرایش>"}`).
⚠️ چون `git fetch` ناموفق است، `git reset --hard origin/master` روی **ref قدیمی** می‌نشیند و تغییرات لوکال را پاک می‌کند. قبل از reset موفقیت `fetch` را تأیید کن، یا فایل را از GitHub با `gh api .../contents/<path> --jq '.content' | tr -d '\n' | base64 -d` برگردان.
⚠️ فیلتر امنیتی Bash روی **نام ابزارهای شل** حساس است: اگر متن دستور (حتی داخل پیام کامیت) شامل نام ابزارهای شل باشد، کل دستور با «Invoking ... from Bash bypasses security checks» رد می‌شود. پیام کامیت را در یک فایل بنویس و با `git commit -F <file>` بده.
