# fa-letterhead — ساخت سربرگ رسمی فارسی

راهنمای تولید سربرگ شرکت/سازمان ایرانی با کیفیت چاپی، از روی فایل موجود یا از صفر.
خروجی: DOCX قابل ویرایش + PDF آماده چاپ، روی A4 کاملاً راست‌به‌چپ.

## گردش کار کلی (۶ مرحله)

1. **بازرسی ورودی** — فایل docx را unzip کن، متن/رنگ/فونت/لوگو را استخراج کن.
2. **آماده‌سازی ابزار** — npm install docx sharp در یک پوشه build؛ بررسی فونت‌های فارسی و Word COM.
3. **تولید گرافیک** — نوارها/موج‌ها/جداکننده‌ها را با sharp از SVG بساز (300 DPI).
4. **ساخت سند** — با docx-js مطابق قواعد این سند (هدر/فوتر = سربرگ، نه در body).
5. **رندر و کنترل کیفیت** — رندر با Word COM + تحلیل پیکسلی اجباری.
6. **تحویل** — کپی docx و PDF با نام فارسی مناسب کنار فایل اصلی.

هر مرحله جزئیاتش در reference مربوطه است؛ فقط همان را بخوان که لازم داری.

## ۱) بازرسی ورودی

```bash
mkdir -p /tmp/lh/orig && cp "<input>.docx" /tmp/lh/orig/orig.docx
cd /tmp/lh/orig && unzip -o orig.docx -d extracted
# متن: grep -o '<w:t[^>]*>[^<]*</w:t>' extracted/word/document.xml
# رنگ‌ها: grep -oE 'srgbClr val="[A-F0-9]{6}"' extracted/word/document.xml | sort | uniq -c
# فونت‌ها: grep -oE 'w:cs="[^"]*"' extracted/word/document.xml | sort | uniq -c
# لوگو/آیکن‌ها: extracted/word/media/
```

از این داده‌ها «شناسنامه برند» را بساز: نام شرکت، نام لاتین، شعار، رنگ اصلی (معمولاً پرتکرارترین
`srgbClr`؛ مثلاً D60000 برای قرمز برند)، رنگ متنی (مشکی/خاکستری)، فونت تیتر و متن، لوگو،
اطلاعات تماس (آدرس/تلفن/ثبت/ایمیل).

**لوگو:** اگر JPG بود، همان را با sharp به PNG و ابعاد ~600px تبدیل کن (بدون پس‌زمینه شفاف لازم
نیست؛ اگر سفید است بگذار سفید بماند). اگر لوگو نبود، از متن + تایپوگرافی بساز.

## ۲) آماده‌سازی ابزار

```bash
mkdir -p /tmp/lh/build/assets && cd /tmp/lh/build
npm init -y > /dev/null && npm install docx sharp --no-fund --no-audit
```

**فونت‌های فارسی — قبل از انتخاب، در رجیستری چک کن:**
```bash
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts" | grep -iE "titr|nazanin|mitra|zar"
```
ترکیب استاندارد مکاتبات رسمی: تیتر = **B Titr** (خانواده «B Titr Bold» → در Word با نام
«B Titr» قابل استفاده)، متن = **B Nazanin**. هر دو تقریباً روی هر ویندوز ایرانی نصب‌اند؛
اگر نبودند جایگزین: Titr / Nazanin / Mitra. برای متن لاتین از Georgia یا Tahoma.

**رندر:** MS Word از طریق COM (ر STL چک کن: `powershell New-Object -ComObject Word.Application`).
اگر Word نبود → LibreOffice headless (`soffice --convert-to pdf`). رندر با Word مهم است چون
فونت‌های B را LibreOffice معمولاً ندارد و نتیجه گمراه‌کننده می‌شود.

## ۳) تولید گرافیک با sharp

همه گرافیک‌ها را از SVG با ابعاد ۳۰۰ DPI بساز (عرض A4 = 2480px). الگوهای اثبات‌شده در
`references/graphics.md` را ببین. مهم‌ترین‌ها:

- **نوار بالای صفحه** (هویت صنعت): 2480×~100px، بدنه مشکی + خط‌چین‌های سفید + بلوک قرمز سمت راست
- **جداکننده سربرگ**: خط مشکی تمام‌عرض + قطعه قرمز ضخیم‌تر از سمت راست (~60% عرض)
- **موج پایین**: دو path منحنی روی هم (رنگ برند روی مشکی)، ارتفاع ~20–24mm صفحه
- **آیکن‌های ریز پاورقی**: pin/phone/برچسب ثبت — SVG ساده stroke رنگ برند

**قانون ابعاد در DOCX:** عرض تصویر در EMU به‌صورت پیکسل × 9525 محاسبه می‌شود؛ در
docx-js واحد `transformation` پیکسل در 96DPI است، پس A4 تمام‌عرض = **794px**. نسبت ابعاد را
دقیقاً از SVG حفظ کن (مثلاً topband 2480×100 → 794×32).

## ۴) ساخت سند با docx-js

قواعد حیاتی (دلیلی که وجود دارند در `references/build-rules.md`):

- **سربرگ در Header/Footer بگذار، نه در body** — تکرار خودکار در همه صفحات + متن نامه هرگز
  روی آن نمی‌افتد.
- **⚠️ باگ docx-js:** هدر `first` در فایل `header1.xml` با مرجع رهاشده ذخیره می‌شود و
  **صفحه اول هدر default را می‌گیرد!** پس: `headers: { default: firstHeader }` — سربرگ
  کامل را به‌عنوان default بگذار و `titlePage: false`. (این تنها راه پایدار است.)
- RTL: هر پاراگراف `bidirectional: true` و هر TextRun فارسی `rightToLeft: true`؛ جدول‌ها
  `visuallyRightToLeft: true`. فونت را در هر چهار اسلات (ascii/hAnsi/cs/eastAsia) ست کن.
- ابعاد: A4 = 11906×16838 twips. حاشیه‌ها: `header: 620, footer: 1250, top: 2410,
  bottom: 1985, left/right: 1300` — سربرگ و پاورقی را با متن بدنه تداخل نمی‌دهد.
- تصاویر تمام‌عرض (نوار بالا، موج پایین) را با `floating` نسبت به PAGE در offset 0 بگذار
  و `behindDocument: true` — از داخل Header، در غیر این صورت در ناحیه چاپی محدود می‌شوند.
- موج پایین: vertical offset ≈ `9975600` EMU (چسبیده به لبه پایین A4).
- ساختار سربرگ: جدول ۳ ستونه RTL [لوگو | بلوک نام | بالانسه] — ستون سمت چپِ خالی برای
  تعادل مرکزی نام ضروری است (بدون آن بلوک نام به چپ می‌کشد).
- فیلدهای نامه (شماره/تاریخ/پیوست): جدول ۶ ستونه label+field؛ فیلد = خط نقطه‌چین پایین سلول
  (`BorderStyle.DOTTED, size: 10, color: 7F7F7F`).
- پاورقی: جدول ۳ بخشی (آدرس | تلفن | ثبت) با `insideVertical` قرمز؛ متن باید روی موج قرار
  گیرد → بگذار بالای تصویر موج شناور باشد، نه داخلش.
- رنگ‌ها را HEX بدون # بده (D60000 نه #D60000).

اسکلت کامل و تست‌شده کد در `references/full-template.md` — کپی کن و شناسنامه برند را جایگزین کن.

## ۵) رندر و کنترل کیفیت (اجباری)

اسکریپت `scripts/docx2png.ps1` (رندر docx→PDF→PNG با Word + WinRT، بدون نیاز به Python) را
با PowerShell اجرا کن:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File <skill>/scripts/docx2png.ps1 \
  -Docx "<abs>.docx" -OutDir "<abs>/qa" -Dpi 130
```

⚠️ اسکریپت را با مسیر مطلق صدا کن (مسیر نسبی از cwd گمراه‌کننده است).
⚠️ **صفحه‌های Word COM گاهی hang می‌کنند** — اگر بیش از ~۲ دقیقه پاسخ نداد، تسک را بکش،
`taskkill //F //IM WINWORD.EXE` کن و inline (نه فایل ps1 بعد از بک‌گراند) دوباره تلاش کن.

سپس تحلیل پیکسلی کن — **کم‌ترین استاندارد را باید پاس کند:**

| بررسی | معیار |
|---|---|
| نوار بالا | پوشش تیره/قرمز در y≈1.2% ≈ 1.0 (تمام‌عرض) |
| بلوک نام | مرکز واقعی: تیرگی نیمه‌راست ≈ نیمه‌چپ |
| قرمز برند | فقط در جای موردنظر (سمت راست نوار، جداکننده، موج) |
| پاورقی | متن تیره خوانا بالای موج + موج در ۳ ردیف پایین |
| صفحه ۲ | یک نسخه دو صفحه‌ای بساز (تست ۳۰+ پاراگراف filler) و هش بیت‌به‌بیت ناحیه سربرگ/پاورقی را با صفحه ۱ مقایسه کن |
| tofu/نمایش نادرست | متن فارسی باید کلاسترهای ناهموار باشد، نه بلوک‌های توپُر پیوسته |

آزمون هش: نواحی سربرگ/پاورقی (top 620px و bottom 290px) باید بین صفحات **بیت‌به‌بیت یکسان**
باشند — این تنها راه مطمئن تشخیص تکرار صحیح سربرگ است (تشخیص چشمی از روی ASCII map).

**محدودیت مهم:** مدل‌های بدون ورودی تصویر (و subagent های judge) نمی‌توانند PNG را «ببینند».
هرگز به «بازبینی چشمی» متوسل نشو؛ تحلیل پیکسلی برنامه‌نویسی‌شده (sharp raw buffer) راه
راستی‌آزمایی است. برای maps ساختاری می‌توانی از ASCII rendering (نمونه در `references/qa.md`)
استفاده کنی تا الگوی عناصر را تأیید کنی.

## ۶) تحویل

```bash
cp /tmp/lh/build/letterhead.docx "<dir-of-input>/<نام شرکت> - سربرگ رسمی.docx"
# PDF هم با Word COM از همان docx (SaveAs2 ,17) کنارش بگذار
```

فایل اصلی کاربر را **هرگز بازنویسی نکن**؛ همیشه فایل جدید کنارش بساز. در پایان خلاصه طراحی
(رنگ‌ها، فونت‌ها، عناصر، نکات فنی) را فارسی گزارش کن.

## قواعد سبکی سربرگ حرفه‌ای

- حداکثر ۲ رنگ برند + مشکی/خاکستری متن. قرمز برند فقط برای: کلمه کلیدی نام، جداکننده، بلوک
  هویتی نوار، موج — نه برای متن بلند.
- تیتر شرکت: B Titr، ۴۰–۴۲ half-point (20–21pt). شعار: ۲۲ half-point bold. پاورقی: ۱۸–۱۹.
  نام لاتین: 17pt با `characterSpacing` ~46 (فاصله حروف، حس رسمی می‌دهد).
- فیلد قابل‌تایپ = خط نقطه‌چین، نه کادر جعبه‌ای.
- فضای سفید مهم‌تر از تزئین است: بین سربرگ و شروع متن حداقل یک «بسمه تعالی» + ردیف فیلدها
  فاصله نفس‌کش باشد.
- گرافیک پایین صفحه هرگز بیش از ~۲۴mm ارتفاع نداشته باشد (فضای امضا را می‌بلعد).
