# iran-dwg-toolkit — تحلیل DWG/DXF + ژئورفرنس روی نقشهٔ واقعی

دو خط‌لولهٔ تست‌شده (۲۰۲۶-۰۹-۱۱، پروژهٔ واقعی جدول‌گذاری نیاسری ماهدشت). اسکریپت‌های آماده در پوشهٔ همین اسکیل (`scripts/`) و نسخهٔ فعال در `~/.zcode/workspace/default/dxf-tools/`.

## پیش‌نیازها (این ماشین)

- **AutoCAD 2027 نصب:** `C:\Program Files\Autodesk\AutoCAD 2027\accoreconsole.exe` (هر نسخهٔ اتوکد معمولی accoreconsole دارد؛ Civil 3D موتورش در core console گیر می‌کند — ازش استفاده نکن)
- Node v22 (بدون پایتون)
- `pdf-build/node_modules` برای playwright-core (تست صفحات نقشه)

## خط ۱: تحلیل DWG (متره/لایه/متن)

```powershell
# یک‌دستوری: DWG → TSV موجودیت‌ها + خلاصهٔ فارسی
powershell -File scripts/analyze.ps1 "C:\path\file.dwg"
```

چه می‌کند: accoreconsole فایل را با `dump.scr` باز می‌کند → `dump.lsp` (LISP خالص با entget — **بدون COM**) همهٔ موجودیت‌ها را به `entities.tsv` می‌ریزد (ستون‌ها: SPACE/TYPE/LAYER/INFO/GEOM) → `analyze.cjs` خلاصه می‌دهد: تعداد بر نوع/لایه، حدود نقشه، بلوک‌ها، متن‌ها، **طول پلی‌لاین‌ها به تفکیک لایه** (برای مترهٔ جدول/آسفالت/دیوار حیاتی).

گاتچاهای حیاتی (هر کدام یک‌بار سخت یاد گرفته شد):
1. **Git Bash پرچم‌های `/i` و `/s` را خراب می‌کند** — accoreconsole را فقط با PowerShell `Start-Process` صدا بزن.
2. **Core Console کام COM ندارد** — `vla-*` خطای «VLA-OBJECT nil»؛ فقط entget/assoc خالص (dump.lsp همین‌طور نوشته شده).
3. **`_.QUIT` آخر اسکریپت hang می‌کند** — پایان اسکریپت = خروج خودکار.
4. `.scr/.lsp` باید ASCII خالص با CRLF (`printf '...\r\n'`).
5. **نام فارسی فایل ورودی → exit 76** — analyze.ps1 خودکار به `input.dwg` کپی می‌کند (اگر دستی اجرا می‌کنی اول کپی کن).
6. ذخیرهٔ DWG از DXF: اسکریپت `_.SAVEAS` ⏎ `2018` ⏎ مسیر مقصد.
7. خطاهای استارت‌آپ `-vbaload farsiEditor.dvb` بی‌ضررند (پروفایل قدیمی).
8. متن‌های فارسی با فونت SHX کدپیج‌دار در TSV به‌هم می‌ریزند (در خود اتوکد سالم‌اند) — اعداد سالم می‌مانند.
9. `ATTRIB` ها در dump.lsp اصلی رد می‌شوند؛ برای اتریبیوت‌ها `geocheck.lsp` را جدا اجرا کن (همچنین `CGEOCS` را چک می‌کند = آیا نقشه ژئورفرنس دارد).

## متره از نقشه

طول پلی‌لاین‌ها را از TSV با Node حساب کن (نمونه در `analyze.cjs`): نقطه‌های GEOM را جدا، جمع hypot، تفکیک بر لایه. برای بهای واحد: فهرست‌بهای راه ۱۴۰۴ فصل ۱۳ (بتن پیش‌ساخته): ردیف‌های ۱۳۰۸۰۱-۱۳۰۸۰۳ جدول بتنی (۲۰٫۱۷۶ تا ۲۵٫۲۰۹ ریال/m³ بر حسب مقطع)، ۱۳۰۸۰۷ جدول پرسی (۳۳٫۵۸۳). حمل تا ۳۰km داخل بهاست.

## خط ۲: ژئورفرنس → گوگل‌ارث/نشان

نقشه‌های پیمانکاری معمولاً **مختصات محلی** دارند (فقط z واقعی است). چک: `CGEOCS=[]` یعنی ژئورفرنس ندارد.

۱. **خیابان/مسیر هدف را از OSM بگیر** (Overpass API):
   - **گاتچا بزرگ: curl در Git Bash فارسیِ query را خراب می‌کند** (همیشه 0-hit می‌دهد). بدنه را با Node بساز: `fs.writeFileSync('ovp-body.txt','data='+encodeURIComponent(q))` بعد `curl --data-binary @ovp-body.txt https://overpass-api.de/api/interpreter`. (Node fetch مستقیم در سندباکس EACCES می‌دهد — ترکیب Node-encode + curl-transport.)
   - مختصات شهر را اول با Nominatim قطعی کن (ماهدشت = 35.73N,50.81E البرز — حدس اولیه می‌تواند کیلومترها خطا داشته باشد).
   - Overpass گاهی 504 می‌دهد → چند بار retry با sleep. خیابان‌ها اغلب چند way جدا هستند → با `chain-niasari.mjs` (اتصال endpoint به endpoint) زنجیره کن.

۲. **برازش سخت‌گیرانه** (`geo-fit.mjs`/`city-match.mjs`): چرخش+انتقال با **مقیاس قفل=۱** (نقشه متر واقعی است). جستجوی سه‌بعدی: s0 (نقطهٔ شروع روی مسیر OSM) × جهت (fwd/rev) × زاویه (±25° دور بردار مماس). **باگ رایج: قبل از چرخش باید نقطهٔ شروع نقشه را کم کنی** (`p0 + R·(p-d0)`) وگرنه RMS چند هزار متر می‌شود.
   - تطبیق کورکورانه قطعی نیست (خیابان‌های صاف امتیاز یکسان می‌گیرند) → **از کاربر نام خیابان/محله را بپرس** یا RMS زیر ~۳۰م را «پیش‌نویس قابل بازبینی» گزارش کن.

۳. **خروجی‌ها** (`build-kml.mjs` با ties.json دو نقطه‌ای = قفل دقیق، یا `build-kml-niasari.mjs` از روی fit):
   - **KML** برای گوگل‌ارث دسکتاپ (نیازمند فیلترشکن) — محور/جدول‌ها/حدود/دیوار/نقاط برداشت با رنگ‌بندی.
   - **پیش‌نمایش HTML** — نسخهٔ نهایی با **OpenLayers + SDK رسمی نشان** در `make-preview-ol.mjs`.

## منابع کاشی از ایران (تست‌شده ۲۰۲۶-۰۹-۱۱)

| منبع | وضعیت | نکته |
|---|---|---|
| ماهوارهٔ گوگل `mt{0-3}.google.com/vt/lyrs=s` | ✅ 200 | سایت گوگل‌مپ فیلتر است ولی CDN کاشی باز! `lyrs=h` روی `lyrs=s` = هیبرید |
| نشان | ✅ از راه SDK رسمی | کاشی‌هایش رمزنگاری‌شده (`tile{n}.neshan.org/{token}.png`) — فقط `new ol.Map({maptype:'dreamy',key:'web.*'})` با SDK `static.neshan.org/sdk/openlayers/5.3.0/ol.js` کار می‌کند. کلید web.* از platform.neshan.org. **سینتکس OL: ساب‌دامین `{0-3}` نه `{s}` لیفلت! زیرلایهٔ group باید visible:true باشد** |
| مپ‌ایر `map.ir/shiveh/{z}/{x}/{y}.png` | ✅ 200 بدون کلید | نقشهٔ فارسی |
| OSM / Wikimedia | ✅ 200 | — |
| Esri/ArcGIS | ❌ 403 | تحریم |
| Bing | ✅ 200 | نیازمند tileUrlFunction با quadkey (در make-preview-ol.mjs آماده) |

گاتچای Leaflet/OL: `L.tileLayer` هدر نمی‌فرستد؛ نشان کلید را هدر/توکن می‌خواهد → حتماً SDK. تست پایپ‌لاین‌های نقشه: `capture-tiles.cjs`/`test-preview.cjs` با playwright-core + کروم سیستم (`NODE_PATH=~/.../pdf-build/node_modules node test-preview.cjs`) — هاست‌های لودشده و خطاها را گزارش می‌دهد.

## گردش کار نمونه (پروژهٔ واقعی)

`D:\dwg\پروفیل ایثار.dwg` (جدول‌گذاری ماهدشت) → تحلیل: ۲٬۸۵۹ موجودیت، ۹۷۸ نقطهٔ برداشت با z واقعی، پروفیل ۰+۰۰۰ تا ۱+۵۰۰ → مترهٔ جدول ۳۶۸٫۱ متر → برآورد فهرست راه → کاربر گفت «خیابان نیاسری اطراف بی‌بی‌سکینه» → Overpass زنجیرهٔ نیاسری → fit با RMS ۳۱م (انتها دقیق روی endpoint ثبت‌شدهٔ OSM نشست) → KML + پیش‌نمایش نشان/ماهواره تحویل دسکتاپ. قفل نهایی دقیق = دو مختصات راست‌کلیک از کاربر (`build-kml.mjs` + ties.json).

## چک‌لیست امنیتی قبل از اشتراک خروجی

- کلیدهای API (نشان/…) را در فایل‌های تحویلی/عمومی نگذار — در اسکریپت‌ها placeholder `__NESHAN_KEY__` بگذار.
- مسیرهای شخصی D:\dwg در گزارش نهایی مهم نیست، ولی کلید هرگز.
